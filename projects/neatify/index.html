Desktop app / file organization

Neatify

Organize a folder. See the changes first.

Python · PySide6 · SQLite

View Neatify on GitHub ↗ (opens in a new tab)

Problem and motivation

File organization needs a way to check changes before they happen. Neatify pairs an arrange preview with recoverable history so users can review a batch and undo it later.

Main functionality

  • Preview file moves before confirming an arrangement.
  • Sort by file type or custom rules, and search within folders.
  • Rename duplicate filenames instead of overwriting them.
  • Review move history and undo previous arrange batches.

Technical implementation

Neatify previews an arrangement before moving files. It renames duplicate filenames instead of overwriting them, records batches in SQLite, and lets users undo past arrangements. Its Python file operations and PySide6 interface connect through the app's sorting rules and saved history.

SQLite is the source of truth for operation history. Small preferences and rules stay in JSON, while the JSONL journal remains a crash-recovery log. The GUI records an entire batch plan before moving files, then commits results after the rename loop.

Recovery and trade-offs

A journal entry alone cannot prove that a file moved. Recovery compares planned paths with the real filesystem and records conflicts when the result is ambiguous.

JOURNAL.md documents a throughput trade-off: the single-file path uses durable journal writes, while GUI batches use SQLite transactions to avoid repeated locks and fsync calls. It also records remaining work around Windows junctions and race-proof renames.
